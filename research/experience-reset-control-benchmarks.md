# 태양계 탐사 경험과 경로 조작 재설계

2026-11-15. 현재 버전의 기능 검사를 통과했다는 사실은 재미나 첫 사용자의 이해를 증명하지 않는다. 이번 변경의 중심은 **상황을 보고 목적지를 고른 뒤, 우주선과 경로를 손으로 바꾸고 결과를 바로 확인하는 탐사**다. 조립 에셋은 유지하고, 화면을 차지하는 설명·중복 도구·계산 오류 반복을 줄인다.

## 권장 경로 조작

1. **대상을 먼저 고른다.** 넓은 3D 태양계에서 행성을 누른다. 해당 천체가 커지고, 짧은 현장 상황과 한 가지 목표만 나온다. 다른 행성은 계속 보인다. 같은 장면에서 다른 목적지로 바꿀 수 있다.
2. **경로는 손잡이로 바꾼다.** 출발점과 미래 도착점이 연결된다. 도착점에는 현재 행성 위치와 다른 미래 위치의 고스트가 있다. 고스트를 해당 행성의 궤도 위로 끌면 시간이 바뀌고, 실제 계산한 궤적과 연료 여유가 따라 바뀐다. 손잡이 자체에 드래그 가능 표시를 주며 `Pe/Ap/R/N/TDB` 같은 초기 장벽은 감춘다.
3. **결과를 조작 옆에 둔다.** 시각적 경로 위에 작은 `도착까지 260일`, `추진 여유`, `관측 기회`만 유지한다. 빠른 길·느린 길은 선의 실제 길이/도착 위치와 함께 바뀐다. 색 외에 선 모양과 상태 문구를 함께 사용한다.
4. **단계 하나만 확정한다.** 현재 필요한 주요 행동은 `이 경로로 출발` 하나다. 실제 실행 전에 계산된 값과 선이 같은 입력의 결과여야 한다. 계산 중인 초안을 이전 유효 경로와 혼동시키지 않는다. 실행 후 시간 진행을 켜고 실제 기체가 계산 경로를 이동한다.
5. **다음 복잡도는 상황에서 등장한다.** 기본 전이를 이해한 뒤 경유 행성을 선택하고, 조우 화면에서 접근 손잡이를 조절해 중력 도움을 설계한다. 단순히 행성을 클릭했다고 Δv를 할인하지 않는다. 연속 경유에는 입·출력 속도와 가능한 회전각이 연결되는 새 물리 계약이 필요하다.

선택 취소는 빈 공간/ESC, 시점 회전은 우클릭, 줌은 휠로 일관되게 유지한다. 첫 화면의 FR/TOP/RT/회전/초점 다섯 버튼은 제거하고 필요 시 `시점 되돌리기` 하나만 둔다. 직접 드래그에는 키보드 대체 입력을 제공하되, 별도 다섯 버튼 열을 상시 띄우지 않는다. 큰 손잡이가 행성을 가릴 때는 투명한 넓은 히트 영역과 작은 시각 요소를 분리한다.

**성능 요구:** 포인터를 움직이는 프레임에 잡힌 손잡이는 먼저 따라가야 한다. 물리 결과가 미완료일 때 표시되는 선은 초안임을 구분하고, 최신 계산만 교체한다. 계산이 무거워지면 Worker를 쓰되 최종 궤적을 자유곡선으로 대체하지 않는다. 큰 장면에서 행성 간 실제 거리와 화면 표시 배율을 분리하더라도 계산 좌표는 유지한다.

## 45초 안에 시작하는 이야기

설정안은 **가상의 탐사 계획인 ‘아스터 관측망’**이다. 지구를 향한 충돌이 이미 확정되었다는 허위 NASA 발표는 쓰지 않는다. 소행성이 보이지 않는 구간으로 들어가 관측이 끊겼고, 현재 데이터로 미래 경로를 충분히 좁히지 못했다는 사건으로 시작한다.

- 0–8초: 관제실 모니터에 세 번 관측된 작은 빛이 지나가고 네 번째 자리에는 신호가 없다. 사람의 짧은 교신: “마지막 점 이후로 보이지 않아.”
- 8–18초: 화면이 태양계로 이어진다. 소행성의 가상 예상 회랑과 지구의 관측선이 태양에 가려진 구간이 보인다. “같은 자리에서는 더 볼 수 없어.”
- 18–30초: 플레이어가 다른 관측 위치를 선택한다. 화면의 가려진 선이 열리면서 선택의 목적을 시각적으로 알게 된다. “그쪽에서 볼 눈을 만들자.”
- 30–45초: 기존 조립실로 들어가 카메라를 직접 붙인다. 필요한 부품 하나가 선반에서 눈에 띄고 실제 장착 위치가 반응한다. 긴 임무 브리핑 대신 달라진 탐사선이 다음 행동을 말해준다.

이후 성공 보상은 추상적인 `4 데이터`가 아니라 **새로운 소행성의 모습·분광 흔적·좁아진 예상 회랑**이다. 새로운 단서가 다른 목적지를 열고, 플레이어가 “어디서 무엇을 알아낼지” 선택하게 한다. 이를 정량적인 실제 충돌확률 계산인 것처럼 표현하지 않는다.

긴급한 지구 충돌을 막겠다고 해왕성까지 수십 년 여행시키는 인과는 맞지 않는다. 첫 사건을 통해 장기 탐사망의 필요성을 보여주고, 이후 내행성 관측, 화성 비교 관측, 외행성/얼음 세계의 기원 탐사를 별도 장으로 이어간다. 각 행성은 같은 체크리스트의 배경 교체가 아니라 에너지·거리·환경·관측 질문이 달라져야 한다.

이 방향은 Outer Wilds의 개발자가 설명한 **호기심이 장소 선택을 이끄는 진행**에서 추론했다. [GDC 개발자 발표 개요](https://www.gdcvault.com/play/1027008). To the Moon의 공식 설명은 한 사람의 구체적인 소원을 따라 기억 조각을 알아가는 구조다. 여기서는 한 문장의 인간적인 문제와 발견의 누적을 참고하며 그 작품의 이야기나 자산을 복제하지 않는다. [Freebird Games](https://freebirdgames.com/games/to-the-moon/).

## 태양계 확장의 과학적 경계

`src/solar/model.ts`는 별도의 명시적 모델이다. 8개 행성의 위치는 JPL의 1800–2050 근사 케플러 요소를 사용하며 지구 값은 지구–달 질량중심이다. 궤도 계산은 기존의 태양 중심 Lambert 풀이와 Kepler 전파를 재사용한다. 모든 경로는 목표의 **도착 시각 위치**로 계산한다. 아스터-7만 창작 천체다. [JPL 근사 위치](https://ssd.jpl.nasa.gov/planets/approx_pos.html).

이 모델은 지도와 입문 탐사용 근사 계획이며 기존 M03의 고정 Horizons 자료/유한 SOI 해와 같은 정밀도로 주장하지 않는다. 실제로 수성·금성·화성·목성·토성·천왕성·해왕성 및 가상 소행성으로 다른 궤적을 계산하지만, 천체 중심의 경계조건은 **착륙·궤도 진입 성공**이 아니다. 태양 중심 비행을 마친 뒤의 근접 비행, 중력 도움, 착륙은 각각의 모델과 검증이 필요하다.

자원 판단은 실제 장착 기체에 연결해야 한다. 계산 가능한 경로와 현재 기체가 실행 가능한 경로는 다르다. 먼 목적지가 연료 부족이어도 경로와 이유는 보여주고, 추진 단계/발사 창을 바꾸는 플레이로 연결한다. 태양에서 멀어질수록 줄어드는 발전량과 늘어나는 통신 지연은 경로 선택의 의미가 된다.

정밀 확장 시에는 각 천체의 Horizons 위치·속도 샘플을 동일한 중심·프레임·시각계로 동결하고 출처/해시를 기록한다. GMAT는 새로운 표본 경로의 오차 검증에 사용한다. 과거 Earth/Mars 시험을 새 천체의 검증으로 재사용하지 않는다. [Horizons API](https://ssd-api.jpl.nasa.gov/doc/horizons.html), [Horizons 매뉴얼](https://ssd.jpl.nasa.gov/horizons/manual.html).

## 변경을 받아들일 최소 증거

- 새 저장 상태에서 긴 설명을 닫는 과정 없이 현재 사건·탐사 목적지·다음 조작이 장면에 나타난다.
- 광학 카메라 선반 강조와 실제 선택 부품이 충돌하지 않는다. 선택/배치 중/장착 완료가 시각적으로 구별된다.
- 처음 켠 지도에서 여러 행성을 고를 수 있고, 둘 이상의 목적지로 실제 다른 경로를 만들고 실행한다. 지도에 이름만 추가한 것을 탐사 완성으로 세지 않는다.
- 숫자 입력 없이 목적지 선택→도착 손잡이 드래그→효과 확인→경로 확정이 가능하다. 드래그 전후 캡처와 실제 계산 결과를 함께 기록한다.
- 잘못된 날짜는 날짜 선택 범위에서 방지한다. 가져온 오류 계획은 가까운 유효 일정/이전 계획으로 돌아갈 수 있다. 변경 없이 같은 실패를 다시 내는 `다시 계산`을 제공하지 않는다.
- 자동 시험은 회귀·상태·반응을 검증한다. 별도의 실제 사용자 관찰 없이 “초보자도 쉽게 이해함”, “재미 검증 완료” 같은 결론을 쓰지 않는다.
