# v9 다음 단일 산출물 제안: 화성 조우를 직접 구하는 3D 임무

2026-11-15 · 읽기 전용 감사/제안 · 구현·사용자 시험 완료 주장이 아님. 확정된 surface-v1 파일, main, 요구 추적표를 수정하지 않았다. native 브라우저와 GPU를 사용하지 않았다.

## 권고

**M03C 「마지막 접근 보정」:** 화성에 접근하는 실제 탐사선의 경로를 마우스로 한 번 고치고, 명령 도착·자세 준비·추진제 조건을 충족해 관측 자료를 지구로 돌려보내는 8~12분 목표의 완결된 챕터를 만든다. 시간은 사용자 시험으로 검증할 목표다. 새 천체, 캠페인, 자유 비행 전체를 한꺼번에 구현하지 않는다.

한 줄 재미: **화성을 빗나갈 예측선을 직접 끌어 관측 회랑에 맞추고, 내가 보낸 명령 때문에 실제 궤적이 꺾이는 순간을 본다.** 더 가까운 관측과 연료·준비 시간 여유 사이에 서로 유효한 두 해법을 만든다. 후자의 과학 품질 차이도 실제 거리·조명·노출·수신에서 계산해야 한다.

## 플레이 흐름

1. **상황을 눈으로 이해:** 실제 저장 기체가 화성을 향하고 있다. 한 문장 목표와 현재 예상 통과점, 관측 가능한 회랑, 마지막 명령 도착 여유만 우선 표시한다. 고정된 교육용 초기 편차를 공개하며 숨겨진 무작위 오차를 추가하지 않는다.
2. **직접 고치기:** 경로를 클릭해 허용 구간에 보정 노드 하나를 놓고 시각을 끈다. 노드의 진행/반경/법선 화살표 또는 화성 앞 접근 평면의 조준점을 끌어 같은 초안을 편집한다. 선이 즉시 따라오고, worker 계산 뒤 실제 가능한 후보·연료·관측 기회가 갱신된다. 축·상태는 선 모양과 문구로도 구분한다. Esc 취소, 미발송 초안 undo, 키보드 대체 입력을 유지한다.
3. **결정과 전달:** 현재 궤적은 실선, 초안은 점선으로 보인다. 명령을 보내면 지상 대기→전파→선상 설치→지구 ACK가 기존 의미를 유지한다. 초안/송신 자체로 우주선이 움직이지 않는다. 이미 보낸 명령은 과거 취소하지 못한다.
4. **실제 결과:** 기체가 실제 자세를 준비하고 허용 조건에서 기동한다. 기동 사건에만 엔진 연출과 실제 경로 분기가 생긴다. 실패·지연 시 기존 경로로 계속 진행한다. 접근점 도달 여부·식·관측·송신은 바뀐 실제 상태로 계산한다.
5. **보상과 재도전:** 큰 화성과 실제 기체를 보여주는 짧고 취소 가능한 조우 카메라 뒤, 수신된 과학 자료와 조준점/실제 통과점을 같은 화면에 남긴다. 고정 초기 조건의 무기동 결과와 자신의 한 번의 변경을 비교하고 재도전한다. 예상선에 기체를 붙여 성공시키지 않는다.

## 그래픽·에셋 선택

**선택안:** 이미 보유한 실제 장착 기체, Mars 표면, 별 배경, 원본 금속 재질·소형 procedural maps, 3D 원뿔/리본/선 geometry를 재사용한다. 효과 자산은 원본 코드 기반으로 만든다. 조준 회랑과 실제 궤적, 분사 방향, 기체 실루엣을 읽기 좋게 만드는 데 예산을 쓴다. 조우 카메라는 기체가 프레임에 남는 안전한 궤도 추적 + Mars limb 중심 구도로 제한하고 사용자가 회전하면 즉시 자동 이동을 멈춘다. 새 대용량 지도는 기본 범위에 넣지 않는다.

대안은 소규모 원본 Blender GLB 노즐/연결부 제작이다. 기존 장비 식별·메시 예산·충돌 형상을 보존할 수 있을 때만 사용한다. 외부 NASA 모델은 해당 모델의 출처·사용 조건·용량·축·UV·LOD 검토가 끝난 뒤 별도 선택한다. 상용 게임 에셋 추출, 유료 생성/구매는 필요하지 않다. 실제 순간 기동에는 짧은 사건 강조를 사용하고, 물리적으로 계속 추진 중인 것처럼 지속 분사하지 않는다.

## 합격 증거

- 수치: 고정 초기 조건에서 무기동 실패, 안전한 통과와 더 가까운 유효 관측의 두 대안, 늦은 명령, 추진제 부족, 자세 준비 실패가 서로 실제 결과로 구분됨. SOI 전환의 위치/속도 연속성, 단위·epoch·중심·원자료 해시, 새 GMAT 표본을 보존한다.
- 실제 사용자 흐름: 마우스로 노드·조준점 드래그→초안 취소→재편집→전송→실제 기동→고유 과학 자료 수신. 우회 QA 버튼이나 성공 JSON 주입으로 대체하지 않는다. 한 번은 무기동 결과와 나란히 비교한다.
- 조작성/시각: 1280x720 및 1920x1080, 큰 UI/효과 감소에서 핵심 기체·손잡이·목표가 가리지 않음. 숫자 입력 없이 필수 흐름 완주. 키보드 대체도 별도 확인한다.
- 재현/회귀: 한 번씩 명령 전파 중과 기동 직후 저장/복구해 연속 실행과 동일 결과. fast warp가 명령·기동·최근접 사건을 건너뛰지 않음. 기존 모델 저장 재생 보존. 문맥 복구/자원 소유권 검증은 새 renderer 경계에 집중한다.
- 성능: 최종 통합 장면만 GPU 독점 상태에서 한 번 측정하고 실제 조건을 기록한다. 장면 전체의 FPS와 포인터 반응 지연을 구분한다.
- 사람: 사용자 5명 중 4명 첫 성공의 원 NFR07는 별도 실제 사람 관찰로 남긴다. 자동 플레이가 증명하는 것은 기능과 재현성이다.

## 벤치마크에서 가져올 것

Juno는 궤도선을 눌러 기동을 계획하고, 노드 gizmo·세밀 조절·행성 카메라와 노드 선택 분리를 제공한다. 여기서는 **행성에 시선을 유지한 채 손으로 조작하고 결과 궤적을 확인하는 상호작용**을 채택한다. [공식 1.1](https://www.simplerockets.com/Releases/View/220866), [공식 1.0.906](https://www.simplerockets.com/Releases/View/223674).

Mars Horizon은 설계·발사 이후에도 자원을 쓰는 관제 판단을 연속적으로 요구한다. 여기서는 **결정→긴장되는 실행→보상이라는 한 판의 호흡**을 채택한다. 턴제 숫자 패널을 그대로 복사하는 제안은 아니다. [개발사 게임 설명](https://aurochdigital.com/marshorizonvideogame).

Solar Smash의 큰 행성과 즉각 반응이라는 원 요구는 노드 드래그 때 큰 화성 옆 실제 후보선과 통과 회랑이 곧바로 움직이는 장면으로 반영한다. 파괴 연출이나 무작위로 달려오는 소행성을 추가하는 것이 아니다. 이 감사의 상용작 비교는 공식 설명과 원 명세에 근거한 설계 추론이며 신규 직접 플레이 관찰은 아니다.
