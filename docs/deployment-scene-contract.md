# Dedicated commissioning scene: isolated implementation contract

This isolated source starts from `orbital-foundry-next-deployment-ui`, the parent's version6-based product worktree and preliminary domain snapshot. It will not overwrite current main, Worker/controller or product panels. Root approved this scene contract before implementation. Type exports are in `src/render/deployment-scene-types.ts`.

## Intended API

`new DeploymentScene(container, callbacks, {earthRadiusKm, quality, reducedMotion})` owns its renderer/canvas, camera controls, scene assets and instance-bound deployment view. Methods are `setCraft(DeploymentCraftView)`, `setSnapshot(DeploymentSceneSnapshot)`, `setPreview(DeploymentPreviewView | null)`, `setPreviewPending(DeploymentPreviewPending | null)`, `setView('workshop' | 'orbit' | 'craft')`, `selectPart`, `selectJoint`, `setWorkshopEditable`, `focusPart`, `focusCraft`, `setViewport`, `render`, `resize`, `getState` and `dispose`. Read-only `qa` exposes canvas, scene mode/snapshot/revisions and projected part/joint positions for actual integrated tests.

The host calls `setCraft` when the immutable topology/source changes; supplied geometry is validated before replacing the old view. Mount-plane origins, orthonormal axes, limits and each part's allowed faces come from the authoritative Worker. A plane is keyed by **partId + face**, not face alone: an internal `py` bay plane and an external `py` hull plane have different authoritative origins. Root generates each allowed plane with `commissioningMount` at zero u/v/rotation and uses that same quaternion's axes. The scene applies no internal/external catalogue heuristics. A pointer ray intersects only the selected part's exact allowed planes, emits face-local u/v candidates and retains the original placement for cancellation. Decorative hangar/stand/lights never enter part selection or mount raycasts. Root owns physical validation, recompilation and undo. No part moves in live-flight mode.

The scene does not call FK, collision/sweep, motor, orbit, success or replay functions. A pending placement request shows a pending marker and hides the last accepted ghost; it never relabels stale geometry as current. Accepted preview source/request IDs remain distinct in `getState`. Escape, capture loss, context loss and visibility loss cancel the gesture and restore its original candidate; actual geometry was never mutated. Hinge callbacks remain the accepted editor-only contract. Arbitrary intermediate releases are not powered commands.

Placement preview includes its complete optional `topology` alongside `geometry`, because moving a part also changes its bus-owned mount-pad local boxes. It must not be applied to the old immutable actual view. The scene owns a separate candidate view/buffers for this topology, validates it independently, and retains the actual view/source untouched. The presentation filter shows the changed part's links and its candidate mount pad rather than an opaque second spacecraft; filtered render geometry is drawn from the supplied candidate boxes/poses, not an independently computed mount. `changedPartIds` may explicitly identify the host's changed part. Hinge/witness previews can omit topology when it is genuinely unchanged. `sourceId` identifies the current actual/base source for stale-response rejection; `requestId` identifies this candidate, and optional `candidateSourceId` records its own source identity.

For `kind:'clearance-witness'`, the supplied geometry must have the witness joint at `firstWitness.sampleAngleRad` (or the first uncertain witness's angle). Mismatched endpoint geometry is rejected. The scene only highlights the exact two supplied box identities. It never invents a swept solid or converts uncertainty to clearance. Root labels the report's sample angle and interval.

## Physical and display frames

The domain owner confirmed `environment.positionKm` is the point-mass whole-craft center of mass. The quaternion maps structural-body axes into **EarthMJ2000Eq**. Time is elapsed SI seconds from **2026-11-15 00:00:00 TAI**, not ICRF/TDB. Physical structural origin is `COM position − quaternion.rotate(geometry.mass.centerOfMassM)/1000` in kilometres. Body-local FK remains unchanged.

Workshop display uses metres and studio lighting. Execution maps the declared inertial frame consistently into Three.js and renders the supplied actual attitude, solar direction, eclipse and station positions at the same committed instant. Explicit host Earth radius/rotation controls the globe. Camera exaggeration is separate from physics: the displayed craft stays centered on orbital COM, with a documented/adaptive display scale that avoids intersecting the real-sized Earth. `getState().display` reports both scale and physical structural-origin metadata. No planet is repositioned to fill the background. Actual trail points must have time at or before the committed snapshot; future prediction is never shown as actual history.

The host owns its animation loop and Worker pause. `render(dt)` updates camera presentation only, never advances domain state. Visibility/context callbacks let the host pause authoritative execution; the renderer cancels input and stops drawing while unavailable. Context retirement must follow the existing version9B ownership rules, including later path rebuild/final disposal.

Use the existing original hangar/workshop visual language and accepted bounded chassis art after its visual gate closes. Workshop fixtures are separate environmental objects. The craft must occupy the UI-safe central area; internal board focus approaches the genuinely open service bay. Orbit/craft cameras preserve player orbit/zoom, exact prior-view restoration and reduced-motion behavior. Initial epoch, source identity and preview status stay explicit.

### Host usage

1. Construct `DeploymentScene`, supply CSS panel insets, then `setCraft` with immutable source/topology and exact per-part mounting planes.
2. Handle placement/hinge callbacks in the controller/Worker; for an in-flight preview request use `setPreviewPending`, then return a matching full-topology placement candidate (or unchanged-topology hinge/witness pose) via `setPreview`.
3. On accepted editor commit, call `setCraft` with the newly identified source. The controller owns undo, physical admission and source revisions.
4. For execution, call `setSnapshot` with one committed instant and `setView('craft')` or `setView('orbit')`. `render(dt)` advances presentation only. Use `setSnapshot(null)` when intentionally ending live execution; an explicit workshop view alone does not silently clear an authoritative snapshot or enable editing.
5. Context/visibility callbacks pause the host's authoritative advance. Resume only after restoration/visibility and the host's own controller checks. Finish with idempotent `dispose`.
