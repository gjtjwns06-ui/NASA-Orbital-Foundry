# 실제 비행 우주선 근접 카메라 제안

2026-11-15. **M03부터 분리 작업본에서 구현·검증한다. 배포된 앱에는 아직 적용하지 않았다.** 기준은 원 기능명세서 사본의 VIS01–04·NFR01/06, 기존 아트 계획과 8C 실제 비행/복구 화면이다. 상용 게임과 동급이라는 판정은 하지 않는다.

## 해결할 구체적 문제

기판·광학계·MLI·실제 장착 모델은 이미 있다. 하지만 비행에서는 그 선택을 가까이서 읽기 어렵다. `GameScene.focusCraft()`는 기체 배치에 관계없이 표시 배율0.25와 고정 카메라 오프셋을 쓰고, 부품별 초점은 조립 화면에서만 가능하다. M03의 지역 시점은 행성 중심이며 기본 카메라 거리가 최소13표시 단위라서 작은 기체가 더 작게 보인다. 새 모델을 더 만드는 것보다 **내가 만든 실제 기체를 비행 중 직접 돌려 보는 화면**이 다음 효과가 크다.

근거 파일: [원 명세](reference-functional-spec-v1.1.md), [아트 제작/출처](asset-provenance.md), [부품 상세 아트](hardware-art-next.md), [이전 직접 조작 계획](next-visual-interaction-iteration.md), [8C 비행 화면](../tests/browser/artifacts/transfer-context-ownership/after-8c/flight-restored-three-times.png), [8C 관제실](../tests/browser/artifacts/transfer-context-ownership/after-8c/control-room-restored-three-times.png).

## 제안하는 사용자 경험

1. 비행 중 **탐사선 보기** 또는 기존 초점 키를 누른다. 실제 장착 부품 전체가 중앙의 사용 가능한 공간을 채우고, 지구/화성의 현재 지평선과 명암이 뒤에 보인다. 첫 구도는 태양광 날개와 관측기 실루엣을 함께 읽는 비스듬한 시점으로 정한다.
2. 오른쪽 드래그는 기체 주위 카메라 회전, 휠은 확대, 외부 부품 클릭은 윤곽과 이름, 더블클릭/F는 해당 부품 초점이다. 기체나 장비를 재배치하는 동작은 아니다. 도구 버튼과 정면/측면/전체 보기로 같은 카메라 조작에 접근한다.
3. 기본 추적은 위치만 따라간다. 실제 자세 제어가 기체를 돌리면 렌즈·패널·안테나도 그 자세대로 움직여 보인다. 사용자가 돌린 시점을 매 프레임 자동 구도로 덮어쓰지 않는다. 조우·수신이 발생해도 자동으로 카메라를 빼앗지 않는다.
4. 전체 궤도 보기/Escape로 돌아가면 해당 비행 단계의 경로·선택·일정 상태는 유지된다. 관제실 전환도 동일한 실제 비행을 유지한다. 동작 줄이기에서는 카메라 전환을 즉시 완료하고 흔들림·자동 회전을 쓰지 않는다.

처음부터 내부를 투시하거나 패널을 펼치는 연출을 추가하지 않는다. 내부 베이 단면 보기는 별도 표시 규칙이 필요하며, 현재 수납 외형을 실제 전개 애니메이션으로 바꾸지 않는다.

## 렌더링 선택

**기존 WebGLRenderer·실제 기체 mesh·NASA 행성 sphere를 그대로 사용하고, 카메라 컨트롤러만 분리한다.** 별도 WebGL 캔버스, 배경 사진, 홍보용 우주선 복제품, 새 고해상도 자산 또는 추가 후처리 패스를 만들지 않는다.

- 기체 크기는 `createBus/createPart`와 실제 `partTransformFor`가 만든 현재 mesh bounds에서 구한다. 6날개·1m반사판·다른 버스를 모두 포함해 맞춘다. 부품 수에 상관없는 고정 거리로 확대하지 않는다.
- 기본 목표는 기체가 **패널을 제외한 중앙 영역의 높이 약45–60%**를 차지하는 것이다. 실제 투영 경계와 UI 사각형을 기준으로 하며, 수치는 캡처로 조정할 계획값이다. 큰 UI에서는 중앙 가용 폭을 다시 계산한다. 중앙 예측 카드는 근접 모드에서 축소해 기체 위를 덮지 않도록 루트 UI와 함께 조정한다.
- 표시 크기 확대는 계속 명시한다. 저고도에서 확대된 기체의 화면상 경계가 행성과 겹치면 표시 배율을 낮추고 카메라를 함께 가까이 가져간다. 물리 위치·부품 간 상대 치수·충돌/가림 반경은 바꾸지 않는다. 카메라는 표시된 행성 표면 밖에 머물고 기체에 맞는 near plane을 사용한다.
- 지구/화성 배경은 **현재 시각의 실제 행성/기체 상태**다. M03 순항에서는 행성이 실제로 멀리 있으므로 큰 화성을 임의로 뒤에 놓지 않는다. 그 구간은 먼 행성과 별 배경으로 보여 주며, 근접 단계 미리보기와 실시간 기체 보기를 섞지 않는다.
- 기존 태양 방향·태양광/금속/광학 재질을 재사용한다. 식 진입을 임의의 조명으로 성공/실패 상태처럼 바꾸지 않는다. 이번 범위에 새 조명·렌즈 재질·텍스처·그림자 품질 조정은 포함하지 않는다.

## 구조와 파일 소유 범위

| 파일 | 변경 범위 |
| --- | --- |
| 새 `src/render/craft-camera.ts` | 카메라/OrbitControls 상태 캡처·복원, 실제 bounds 기반 fit, 위치 추적, 줌/행성 경계, 사용자 조작 이후 자동 구도 중단. 렌더러·재질·물리 상태를 소유하지 않는 컨트롤러 |
| `src/render/scene.ts` | 기존 `focusCraft()`를 명시적 근접 모드로 연결. `setFlightFrame()`의 실제 위치/자세 이후 추적 갱신. 비행 중 부품 raycast는 읽기 전용 선택으로 분리 |
| `src/render/transfer-scene.ts` | 같은 컨트롤러 재사용. `setEpoch()/setAttitude()` 상태를 따라가며, 활성 단계의 동일 ICRF 축으로 동작. SOI/표시 좌표계 변경 때 상대 시점과 기체의 화면상 크기를 보존 |
| 루트 소유 `src/main.ts`, `src/transfer-ui.ts` 및 관련 CSS | 근접/전체 토글, 선택 부품 이름, 표시 배율 안내, 키보드 경로, 큰 UI의 중앙 영역과 예측 카드 위치. 명령 전송/임무 계산 경로는 변경하지 않음 |
| 새 카메라 단위·브라우저 시험 | 물리 상태 불변, 다양한 실제 조립의 투영 경계, 포인터/휠/부품 초점, 복귀, 단계 전환, 반복 진입/복구, 두 언어/큰 UI |

구현 순서는 검토 후 **M03 활성 단계·SOI 전환부터**로 확정했다. `orbital-foundry-next-camera`의 새 컨트롤러와 `transfer-scene.ts`만 먼저 구현하며, `GameScene`·주 앱·전이 UI는 이 단계에서 수정하지 않는다. M03 `autoFrame`과 근접 컨트롤러가 동시에 카메라를 움직이지 않게 단일 소유자를 정한다. 모델·NASA 맵·질량/전력/통신 데이터는 수정하지 않는다.

지역 장면의 최소 근점 간격으로 전체 기체 표시 반경·카메라 회전 반경을 함께 제한한다. 따라서 어떤 회전 방향에서도 카메라가 실제 행성 표면을 침범하지 않는다. 태양 중심 순항의 근접 모드에서는 행성도 거리와 같은 물리 축척으로 표시한다. 기존 전체 보기용으로 확대된 지구 구체가 실제 SOI 직후 탐사선을 삼키는 모순을 피하며, 전체 보기로 복귀하면 기존 설명용 확대를 되돌린다. 실제 비행 데이터는 변하지 않는다.

제안 API는 `setCraftInspection(enabled)`, `getCraftInspectionState()`, `focusInspectionPart(id|null)`, `setInspectionViewport({left,right,top,bottom})`이며 마지막 값은 CSS 픽셀 인셋이다. 선택 콜백은 부품 ID만 알리고 설계나 명령 상태를 변경하지 않는다. 다른 시점의 단계 미리 보기에서 진입해도 실제 현재 단계로 이동하며, 종료 때 이전 시점·카메라 설정을 복원한다.

## 수용 기준

- 동일 저장 비행에서 카메라를 조작하기 전후의 위치·자세·연료·전력·패킷·명령 기록이 동일한 시각에서 같다. 카메라 입력은 Worker 명령이나 새 일정 입력을 만들지 않는다.
- 1280×720, 한국어/영어, 기본/큰 UI에서 균형 기체·6날개·반사판 조합의 전체 기체가 가용 영역에 보이고, 실제 외부 부품 클릭·확대·복귀가 가능하다. 중앙 UI가 기체의 핵심 형상을 가리지 않는다.
- 정지 중 카메라를 움직여도 물리는 정지한다. 실제 자세 기동 중에는 동일 장착 상태로 기체가 움직인다. 고속 진행·SOI 전환·저장 복원에서 카메라가 행성 내부로 들어가거나 다른 시점의 배경으로 바뀌지 않는다.
- 30회 근접/전체/관제실 전환 후 GPU 자원이 첫 안정 상태로 돌아온다. 실제 컨텍스트 손실/복구 뒤 비어 있는 화면·중복 캔버스·잘못된 GPU 삭제가 없다.
- 기존 표준 NFR01 측정은 유지하고, 새 근접 화면의 120초 입력 재생을 **별도 장면**으로 추가한다. 실제 측정 전 성능 통과를 선언하지 않는다.

이 기능의 완료 증거는 실제 플레이 화면과 직접 조작이다. Blender 미리보기나 썸네일을 근접 비행 화면의 구현 증거로 대신하지 않는다.
