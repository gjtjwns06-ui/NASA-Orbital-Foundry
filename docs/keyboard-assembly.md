# Keyboard assembly candidate

Status: integrated into the local version8 candidate after development from published baseline `e34088c6`. The private live site is still version7. The earlier isolated evidence below is retained with its original scope.

VIS05 requires alternatives to dragging; QA17 includes essential interaction in both languages, larger UI and reduced effects. This slice covers mounting and moving spacecraft components, including the actual service bay. It does not complete timeline/navigation keyboard alternatives, whole-game accessibility, or NFR02's measured100ms input-to-display requirement.

The existing mouse controls remain the primary interaction. Native Enter or Space on a hardware shelf button starts an uncommitted 3D ghost. The installed-parts list opens an existing part for editing. A labeled face selector and U/V metre/rotation inputs offer a numerical alternative. With the movement pad focused, arrows change mounting coordinates by2cm (Shift5mm); R/Shift+R rotate±15°. Enter confirms, Escape cancels. Native field key behavior is retained.

Both input routes use unchanged `evaluatePlacement`, and Confirm calls the same shared placement commit function as the pointer. A successful edit creates one ordinary undo checkpoint. A ghost cannot mutate the craft or be saved; invalid placement, incomplete/nonfinite numeric input and a changed source design cannot commit. Cancel restores the view saved at edit entry, bay/stow state and prior selection. Confirm retains the chosen editing view. All41 pinned normalized physical engine source identities remain unchanged.

Implementation is limited to `src/keyboard-assembly.ts/.css` plus narrow `main.ts` and `render/scene.ts` patches. New render resources use the existing pointer ghost ownership/disposal pattern; individual key nudges reuse geometry/materials. Extremely distant invalid numeric candidates hide the ghost rather than upload an overflowing transform to the GPU.
