# Orbital Foundry 구현 계획과 완료 판정

2026-11-15 · 웹 브라우저 우선 · 실제 3D · 사용자 승인 범위: 계획부터 구현·반복 검증까지 자율 진행

## 최종 목표

Mars Horizon의 읽기 쉬운 입체 시설과 아름다운 행성 연출, Juno: New Origins의 직접 조립과 기동 편집, Solar Smash의 즉각적 시각 반응을 참고하여 독자적인 3D 우주 임무 설계 게임을 만든다. 원본 게임의 코드·모델·음악·화면 구성을 복제하지 않는다. **상용 게임과 동급의 전체 규모·완성도라는 목표는 시각·기능·사용성 증거 없이 달성했다고 선언하지 않는다.** 기존 기능명세서 v1.1을 원 요구로 유지하며, 아래 제작 단계는 범위를 임의로 축소하는 완료 선언이 아니다.

## 제작 전 조사와 결정

- Mars Horizon: 과학 임무 → 탑재체/발사체 → 발사 → Mission Control의 명확한 흐름을 적용한다. 원작의 턴제 숫자 퍼즐을 그대로 재현하지 않고 물체·경로·시간을 직접 편집한다. [공식 소개](https://store.steampowered.com/app/765810/Mars_Horizon/)
- Juno: 궤도 클릭의 문맥 조작, 드래그 기동 핸들, 카메라/부품 입력 분리와 일관된 화면 감도. 핸들 클릭 우선순위와 오래된 예측 덮어쓰기를 회귀 검증한다. [공식 1.1](https://www.simplerockets.com/Releases/View/220866), [1.0.9](https://www.simplerockets.com/Releases/View/221916), [1.4](https://www.simplerockets.com/Releases/View/340106)
- Solar Smash: 대형 천체 장면의 직접 반응을 참고한다. 파괴 무기 대신 관측 빔, 교신선, 스윙바이 궤적과 과학 결과로 보상한다. [개발사 등록 설명](https://play.google.com/store/apps/details?hl=en-US&id=com.paradyme.solarsmash)
- 그래픽: 실루엣 → 기능 모듈 → 접합부 순으로 디테일을 만든다. 흰색 도장/남색 구조재/금색 단열/청색 태양전지를 재질로 구분한다. 시설은 밝은 스타일화, 우주는 실제 천체 텍스처와 절제된 대기광. Blender로 시설 GLB를 만들고 Three.js에서 게임 부품을 조립한다.
- 브라우저: TypeScript/Vite/Three.js, 물리 Float64와 화면 좌표 분리, Worker 예측, 고정 시간 간격, IndexedDB 및 JSON 백업. 외부 AI API 없이 실행한다.
- GMAT: 제작 PC에서 실제 실행한 기준 궤적만 검증 자료로 포함한다. 브라우저에 GMAT 실행파일을 넣거나 이미 검증됐다고 가정하지 않는다.

## 수용 기준과 증거

1. 시작 화면·조립실·Earth 궤도·Mars 스윙바이·결과의 다섯 장면을 실제 브라우저 스크린샷으로 검토한다. 3D 조작 없이 배경 이미지로 위장하지 않는다.
2. 부품 선반에서 기체로 드래그하고 부품을 다시 잡아 옮긴다. 카메라 회전과 충돌하지 않으며 이동/회전/취소/삭제/되돌리기가 일관된다.
3. 궤도 핸들 및 Mars 접근점을 마우스로 바꾸면 궤적·연료·결과가 갱신된다. 불가능한 경로는 이유를 표시한다.
4. 지구관측과 화성 스윙바이 임무 각각 성공 및 실패 경로를 실제로 실행한다. 실패 원인은 배치·경로·운영 선택으로 설명한다.
5. 서로 다른 시간 배율 및 저장/복원에서 같은 명령은 같은 결과를 낸다. 다른 탭·WebGL 컨텍스트 손실은 일시정지한다.
6. 무효 저장·저장 차단·미지원 그래픽을 처리하고, JSON 입출력과 로드 후 네트워크 단절을 검증한다.
7. 기동 에너지·궤도 보존·배터리 W/Wh·데이터 bit·중복 과학 결과에 의미 있는 자동 검증을 둔다.
8. GMAT 기준 데이터의 실행 버전·스크립트·좌표·단위·시각·오차를 기록한다. 미검증 영역은 그대로 표시한다.
9. 1280×720 및 1920×1080에서 주요 조작이 잘리지 않고, 브라우저 콘솔 차단 오류/실패 자산 요청이 없다.
10. 원 기능명세서의 57개 요구와 QA01–20을 추적한다. 테스트 불가능한 외부 사용자 5명 평가 등은 자동 PASS 처리하지 않는다.

## 반복 방식

요구 확인 → 구현 → 단위/통합 검사 → 실제 브라우저 드래그·완주 → 스크린샷 검토 → 오류 및 원 명세서 미달 수정 → 재검증 순으로 진행한다. `docs/iteration-log.md`에 확인한 사실, 수정, 남은 항목을 기록한다.

Ouroboros Ralph MCP 도구는 현재 연결되어 있지 않다(도구 목록과 플러그인 검색 확인). 따라서 이 세션의 반복 작업을 Ralph 백그라운드 작업이나 검증된 Seed 실행으로 표시하지 않는다. 실행 가능한 런타임이 연결되면 해당 스킬의 정식 워크플로로 이어갈 수 있다.

기준은 테스트를 통과시키려고 약화하지 않는다. 상용작 전체 규모와 비교하는 최종 목표를 미달이면 미달로 남긴다. 사용자 입력이나 외부 조건이 필요하지 않은 구현은 계속 진행한다.
