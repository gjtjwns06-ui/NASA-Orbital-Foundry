# 다음 직접 조작·그래픽 개선안

2026-11-15. **계획만 작성했으며 이 문서로 제품 코드를 바꾸지 않았다.** 기준은 최종 B-z 빌드, [요구사항 감사](requirements-matrix.md), 현재 `parts.ts`·`scene.ts`·`stow.ts`·`transfer-scene.ts`·`transfer-ui.ts`의 동작이다. NASA 자료 기반 하드웨어 확대는 다른 작업에서 준비 중이며, 아직 들어오지 않은 종류·검증 수치를 구현 완료로 세지 않는다.

다음 한 번의 구현은 **“화성 접근점을 직접 잡아 바꾸기 + 선택한 하드웨어의 차이를 3D로 읽기”**에 집중하는 것이 효과적이다. 기존 B-plane·고도 계산과 실제 부품 부착을 이용하므로 새 애니메이션만 늘리는 것보다 사용자의 선택과 결과를 연결하기 쉽다. 그 뒤 모델과 함께 패널 전개를 넣는다.

## 현재 체감의 빈 곳

- 날짜 손잡이와 부품 드래그는 실제로 동작한다. 그러나 화성 조우 각도·고도는 아직 슬라이더이고, M03 발사 뒤에는 경로·운영을 바꾸는 직접 대응이 없다.
- 기체는 장착 위치대로 만들어지지만 부품의 기능과 축을 가까이서 읽기 어렵다. 향후 부품 종류가 늘 때 단순 크기·색 변형만으로는 선택의 이유가 보이지 않는다.
- 수납 검사는 정적 외형 교체다. `stow.ts`도 인증된 접힘 기구나 전개 애니메이션이 아님을 명시한다. 패널 경첩·전개 중 간섭·전개 상태별 실제 발전은 아직 하나의 모델로 연결되지 않았다.
- M03 탈출 단계는 질량·연료·비용을 계산하지만 단계 자체의 장착·분리 장면은 없다. 기존 발사 장면도 일반 연출이고 선택한 로켓/발사장 대기 비행 시뮬레이터가 아니다.
- 관제실의 live 화면은 실제지만 책상과 운영요원은 정적이다. NPC 연출은 현재 설계 의사결정을 바꾸지 않으므로 먼저 할 필요는 낮다.

## 우선 작업과 완료 기준

| 순서 | 사용자가 하는 행동 | 필요한 구현 | 완료를 확인할 증거 |
|---|---|---|---|
| 1 · 다음 범위 | Mars 상세에서 접근점 원형 손잡이를 드래그해 고도/조우면을 바꾸고, 이전 경로와 비교한다 | 기존 고도·B-plane 입력의 같은 계산 경로를 사용. 입사 점근선 기준 조우 평면과 손잡이, 반경/각도 조작을 분리. 계산 중 이전 승인 경로는 점선·대기 문구로 표시하고 새 계산 성공 뒤에만 확정. 날짜와 같은 포인터 취소·슬라이더/키보드 대안 유지 | 실제 포인터로 두 축을 바꿔 전체 Earth→Sun→Mars 경로·C3·연료·성과가 다시 계산됨. 경계 밖/미수렴 시 발사 차단, 빠른 연속 드래그에서 오래된 해를 채택하지 않음. 1280×720에서 양 옆 패널에 손잡이가 가려지지 않음 |
| 2 · 다음 범위 | 새 장비를 집으면 기능 축과 장착면이 보이고, 놓는 순간 어떤 제약이 바뀌었는지 이해한다 | 새 hardware definition마다 원본 render profile: 실제 외형 치수, 장착점, 카메라 광축/안테나 boresight/패널 법선, 충돌 박스 연결. 기존 palette·ghost·확정 모형을 같은 factory에서 생성. 선택 부품만 선명한 윤곽·장착면 투영·기능 축을 보이며 현재 검사 모드와 연동 | 새 각 부품의 면·회전·크기가 검사와 일치. 같은 면 이동으로 가림/간섭이 실제 바뀜. 교체·복제·undo·save/load 후 형상/물리 값 동일. 부품 이름만 다르고 동일 기능인 가짜 선택지를 늘리지 않음 |
| 3 · 모델 확장 후 | 조립대에서 패널 경첩 손잡이를 잡고 접고 펼치며 걸리는 지점을 발견한다 | 경첩 pivot·관절 각·분절 치수·전개 상태를 공유 정의로 둔다. 렌더와 충돌/발전/가림이 같은 transform 사용. 중간 각도의 swept-volume 검사가 준비되기 전에는 정적 외형을 전개 안전 판정으로 부르지 않음 | 두 유효 배치 중 하나가 전개 중 충돌하고 다른 하나는 통과. 각도별 면적·태양 입사·가림과 실제 W가 일치. 한 번의 확정이 한 undo 단위, 취소·반복 복원 결정론 유지 |
| 4 · 실행 이벤트 후 | 실제 탈출 단계가 붙어 있고, 성공한 기동·분리·전개가 기체에서 보인다 | `mission time/event ID`로 구동되는 표현 상태. M03의 현재 순간 기동 가정은 그대로 공개하고 유한 추력 적분처럼 보상하지 않음. 질량 회계가 분리되는 순간에만 모델 단계도 분리. 패널 전개가 과학 상태라면 같은 상태를 저장·복원하고 전개 전 발전/지향도 모델에 반영 | pause/warp/save/load/replay가 같은 상태를 재현. 기동 실패 때 성공 경로를 따라가지 않음. 카메라 자동 연출은 건너뛰기 가능하며 reduced motion에서 정보가 유지됨 |
| 5 · 이후 | 실패한 전력/교신 사건을 누르면 관련 시간과 부품으로 돌아가 한 가지를 고친다 | 결과의 실제 사건 ID→시간/operation/part ID 연결, 원 상태와 수정 상태를 한 화면에서 비교. 경고 대상의 3D 윤곽·광선·자세를 보여 주고 A/B 모델 조건 일치 검사 | 같은 입력을 재생하면 같은 원인, 한 번의 수정으로 실제 자원·수신 결과가 달라짐. 장식적인 빨간색 표시만으로 실패를 설명하지 않음 |

첫 두 항목은 **계획 단계 직접 조작의 개선**이다. 이것만으로 비행 중 TCM·지상 명령·계획 변경을 구현했다고 표기하지 않는다. 실제 상태에서의 보정은 별도 궤도/연료/명령/저장 계약을 가진 작업으로 남긴다.

## 에셋 제작과 표현 규칙

- 기존 ivory/navy/teal/amber, 금색 MLI·청색 태양전지·은색 프레임을 유지한다. 기능이 다른 부품은 렌즈·라디에이터·반사판·노즐 등 실루엣으로 구별하고 작은 라벨은 확대 시에만 보인다.
- NASA·제조사 문서의 **수치 출처와 형상 출처를 구분**한다. 치수/사진만 참고해 만든 원본 간략 모델은 해당 제품의 공식 CAD나 정확 복제품으로 표시하지 않는다. 제조사 파일은 재배포 라이선스가 확인된 경우에만 포함한다.
- 새 조립 부품은 기존 `createPart` 경로와 같은 장착 좌표계로 만든다. 움직이는 부분만 pivot 그룹을 나누고 고정 구조는 재질별 합친 mesh로 유지한다. 공통 금속/태양전지 재질·반복 볼트 geometry를 재사용하고 선택 강조용 재질의 소유권을 분리한다.
- 절제된 접촉 그림자·모서리 하이라이트로 조립 위치를 읽게 한다. 새 화면 전체 bloom이나 모형별 고해상도 텍스처를 먼저 추가하지 않는다. 서로 다른 반사 재질·한 개의 공통 상세 atlas로 시작한다.
- 자세·기동 표시에는 실제 시간과 계산 상태를 사용한다. 연출용 과장 크기·가속·단계 미리보기는 명시하며 물리 상태를 애니메이션이 다시 쓰지 않는다.

## 성능·검증 경계

현재 최종 빌드의 6부품 기준에서는 관제실과 실제 M03 Mars가 각각120초/7,203프레임, p99 17.0ms, >33.34ms0, 오류0이었다. 관제실은213 geometry/24 texture/34 program, M03는115/9/24로 20초 간격6표본 동안 일정했다. [측정 원본](../tests/browser/artifacts/performance-extended/report.json)은 이 PC의 따뜻한 장면이며 전체 품질을 보증하지 않는다.

신규 부품·관절 후에는 유효한 여러 장비 조합으로 다음을 다시 확인한다.

1. 반복 선택/교체/접기/취소/미션 전환 30회 후 GPU geometry·texture가 첫 안정 상태로 돌아온다. context 복구와 닫기 이후 canvas/renderer가 남지 않는다.
2. 1280×720 한·영/큰 UI에서 손잡이와 중요 경고가 보이고 실제 포인터로 조작된다. 키보드·슬라이더 대안과 reduced motion도 같은 모델 결과를 만든다.
3. 원 NFR01의 **1080p 중간·20부품·2천체·약1,000점·10초 준비 후120초 입력 재생·평균60fps/p99≤33.3ms**는 별도 실행한다. 20개를 합법적으로 조립할 수 없는 현재 모델이면 그 제약을 먼저 기록하고 단순 장식 복제로 충족시키지 않는다.
4. 기존 완주·저장·수신 결과는 같은 입력에서 유지하고 새 기능에만 모델 버전 변경을 적용한다. 화면 캡처·단위 시험·실제 사용자 이해도는 서로 다른 증거로 남긴다.

이 개선안은 장비 선택의 손맛과 결과 이해를 우선한다. 상용작과의 시각 동급, 모든 하드웨어 종류의 구현, 안전한 전개 기구 완성을 미리 선언하지 않는다.
